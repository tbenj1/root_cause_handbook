# Information Gathering

Good troubleshooting starts with good information. The goal is to understand the issue well enough that another IT professional could read the notes and know exactly what is happening.

## Who Is Affected?

Ask:

* Who is having the issue?
* Is the person reporting it also the person affected?
* Is it one person or multiple people?
* Is an entire department, office, or organization affected?
* Is it one device or multiple devices?
* Do the affected users have anything in common, such as the same application, device type, network, or location?

This helps you see whether the issue is tied to:

* A user
* A device
* An application
* A location
* The organization
* A service

### Example

If one user cannot access a file, check that user’s permissions, account, application, and device.

If nobody in the organization can access the file, the issue is more likely tied to the server, service, network, or a permission applied to a larger group.

## What Is Actually Happening?

Ask the user to explain exactly what they are trying to do and what happens when they try.

Useful questions include:

* What are you trying to do?
* What should happen?
* What happens instead?
* Is there an error message?
* Is there an error code or reference number?
* Can you send a screenshot?
* Does the application freeze, close, load slowly, or fail to open?
* Does the issue happen every time?
* What exact steps make it happen?

Do not stop at descriptions such as:

* “It does not work.”
* “The computer is slow.”
* “The internet is down.”
* “My email is broken.”

Keep asking questions until the behavior is clear enough that someone else could understand it or reproduce it.

### Example

Instead of documenting:

> Outlook is not working.

Document:

> The user can open Outlook, but new messages stay in the Outbox. The issue started this morning. Outlook shows “Disconnected” in the lower-right corner. The user can still access websites.

## Where Is It Happening?

Ask:

* Are you working from home or in the office?
* Which office or location are you in?
* Are you using Wi-Fi or Ethernet?
* Are you connected to the company VPN?
* Are you using a company device or a personal device?
* Are you working from a local computer, Remote Desktop, a virtual desktop, or a terminal server?
* Does the same issue happen from another location or network?

The location can point toward:

* An office internet connection
* Wi-Fi
* VPN
* A firewall
* Remote access
* A site-specific server
* A power or ISP outage
* Home network equipment

## When Did It Start?

Ask:

* When did it first happen?
* Was it working before?
* When was the last time it worked correctly?
* Does it happen every time or only sometimes?
* Does it happen at a certain time of day?
* What changed before it started?
* Was the computer restarted, updated, moved, or replaced?
* Was software installed or updated?
* Was a password changed?
* Were any permissions, network settings, or security tools changed?

Compare the timing with:

* Windows updates
* Application updates
* Password changes
* Account lockouts
* Server maintenance
* Network outages
* Software installations
* Policy changes
* Security deployments

## What Is the Impact?

Ask:

* Is the user completely unable to work?
* Is there a workaround?
* Is a critical business process affected?
* Is customer-facing work affected?
* Is a deadline or meeting being impacted?
* Is data missing, unavailable, or at risk?
* Is there a possible security issue?

The impact helps set the right priority and shows whether the issue needs immediate escalation.

## What to Document Before Troubleshooting

Document:

* User or users affected
* Device or devices affected
* Location and connection type
* Exact symptoms
* Exact error message or code
* When the issue started
* Last known working time
* Steps to reproduce the issue
* Recent changes
* Business impact
* Any workaround already being used
